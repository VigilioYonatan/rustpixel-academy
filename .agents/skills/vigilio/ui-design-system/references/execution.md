# Ejecución — ui-design-system

## Protocolo

1. Leer `SKILL.md` completo, Docs canónicos aplicables y archivos de proyecto.
2. Evaluar usuarios, plataforma, input, seguridad y diferencia entre deseo visual/contrato implementable.
3. Revisar el diseño existente antes de generar un nuevo sistema; escoger la mínima solución coherente.
4. Documentar variantes, estados, errores, foco, pruebas y regresiones de componentes.
5. Implementar solo si fue pedido; ejecutar gates; revisar sin modificar y retornar evidencia.

## Negativos

- Un estilo genérico no es diseño de producto.
- Los mocks no demuestran interacciones reales.
- Una captura, test estático o score de contraste no demuestra WCAG integral.
- No tocar archivos/systems de terceros ni subir datos confidenciales a Figma/IA sin autorización.

## Contrato de salida

`stack_detectado`, `skills_realmente_leidas`, `fuentes_leidas`, `decisiones`, `tradeoffs`, `tests`, `a11y`, `performance`, `review`, `pendientes`.
