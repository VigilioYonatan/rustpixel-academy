# S11 · Cascada de saturación

**Tipo:** reto guiado Senior Rust · **ID:** S11-C01 · **Estado:** material práctico preparado; no prueba de ejecución.

## Contexto profesional

Una dependencia lenta agota el pool de conexiones y propaga fallos.

## Objetivo del laboratorio

Aplicar timeouts, límites de concurrencia y backpressure.

## Restricciones y trade-offs

- Preservar cancelación y mensajes operativos útiles.
- Toda afirmación de corrección debe incluir evidencia o describirse como hipótesis.

## Artefacto para inspección

**queue.config · saturación** (ejemplo didáctico; no salida real del compilador)

```text
queue_capacity = unlimited
producer_rate = 5000/s
consumer_rate = 300/s
```

**Pregunta del reviewer:** Propón límites y una política medible de rechazo, espera o persistencia.

## Decisión de diseño

Una cola ilimitada agota memoria durante un pico; ¿qué implementas?

- **Opción A:** Aumentar RAM indefinidamente
- **Opción B:** Límites de cola, backpressure y políticas de rechazo/reintento
- **Opción C:** Crear más tasks sin límite

1. Cola crece
2. Se identifica falta de límites
3. Se ejercita saturación y rechazo controlado

3. Define una prueba que fallaría si el problema regresa.
