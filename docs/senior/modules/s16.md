Un módulo antiguo mezcla API, SQL y lógica de negocio.

## Objetivo del laboratorio

## Restricciones y trade-offs

## Artefacto para inspección

**compatibility.diff · API cambiante** (ejemplo didáctico; no salida real del compilador)

```diff
- GET /v1/order/:id -> {"id":1,"status":"paid"}
+ GET /v1/order/:id -> {"id":1,"state":2}
```

**Pregunta del reviewer:** Justifica tests de contrato y una migración sin rotura.

## Decisión de diseño

Debes modernizar un servicio sin romper consumidores; ¿qué propones?

- **Opción A:** Crear tests de contrato, migrar por incrementos y medir regresiones
- **Opción B:** Reescribir todo sin pruebas
- **Opción C:** Cambiar formato de respuesta sin aviso

## Quality gates recomendados

- Ejecutar `cargo fmt --all -- --check` y `cargo check --all-targets` en el crate del ejercicio.
- Ejecutar `cargo clippy --all-targets -- -D warnings` y `cargo test` cuando exista un paquete Cargo completo.
- Registrar entorno, versión de toolchain, código de salida y fallos.
- Para async, concurrencia y performance: pruebas de cancelación, estrés, benchmarks o fuzzing según el riesgo, sin fingir resultados.
