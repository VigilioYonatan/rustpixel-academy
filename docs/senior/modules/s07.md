# S07 · Tareas huérfanas en shutdown

**Tipo:** reto guiado Senior Rust · **ID:** S07-C01 · **Estado:** material práctico preparado; no prueba de ejecución.

## Contexto profesional

Un servicio Tokio crea tasks sin conservar JoinHandle.

## Objetivo del laboratorio

Implementar task ownership, cancelación cooperativa y shutdown acotado.

## Restricciones y trade-offs

- No detener sin drenar trabajos aceptados según contrato.
- Toda afirmación de corrección debe incluir evidencia o describirse como hipótesis.

## Artefacto para inspección

**src/server.rs · task sin propietario** (ejemplo didáctico; no salida real del compilador)

```rust
async fn handle(job: Job) {
    tokio::spawn(async move { process(job).await });
    // The caller never joins or cancels the spawned task.
}
```

**Pregunta del reviewer:** Propón un ownership explícito del JoinHandle, cancelación y cierre ordenado.

## Decisión de diseño

Tokio deja tasks vivas tras cerrar el servicio; ¿qué haces?

- **Opción A:** Rastrear JoinHandles, propagar cancelación y esperar shutdown con timeout
- **Opción B:** Lanzar tasks con spawn y olvidarlas
- **Opción C:** Abortar todas las tasks sin revisar persistencia

## Revisión de referencia (leer tras resolver)

**Alternativa guiada:** A

La cancelación cooperativa y join de tareas son parte de la propiedad del ciclo de vida; abortar sin analizar efectos puede perder datos.
