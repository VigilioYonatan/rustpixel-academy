# S01 · Copy vs Clone bajo carga

**Tipo:** reto guiado Senior Rust · **ID:** S01-C01 · **Estado:** material práctico preparado; no prueba de ejecución.

## Contexto profesional

Un parser crea cientos de String clonados al extraer prefijos de rutas.

## Objetivo del laboratorio

Refactorizar la API para prestar vistas sin retener datos de vida insuficiente.

## Restricciones y trade-offs

- Evitar clones por defecto; la firma pública debe tener lifetimes legibles.
- Toda afirmación de corrección debe incluir evidencia o describirse como hipótesis.

## Artefacto para inspección

**src/parser.rs · clonación innecesaria** (ejemplo didáctico; no salida real del compilador)

```rust
pub fn prefixes(paths: &[String]) -> Vec<String> {
    paths.iter()
        .map(|p| p.split('/').next().unwrap_or("").to_owned())
        .collect()
}
```

**Pregunta del reviewer:** ¿Puede devolverse una vista prestada? ¿Qué lifetime asociarías al slice de entrada?

## Decisión de diseño

El perfil revela 25 000 clones de String por segundo; ¿qué haces primero?

- **Opción A:** Reemplazar todos con referencias sin revisar lifetimes
- **Opción B:** Perfilar la ruta y cambiar a &str donde el ownership permita vistas
- **Opción C:** Usar unsafe para evitar copias
