# S06 · Deadlock intermitente

**Tipo:** reto guiado Senior Rust · **ID:** S06-C01 · **Estado:** material práctico preparado; no prueba de ejecución.

## Contexto profesional

Dos tareas bloquean un Mutex y un RwLock en orden inverso.

## Objetivo del laboratorio

Definir y aplicar orden total de locks y reducir duración de sección crítica.

## Restricciones y trade-offs

- Evitar retener locks sobre I/O.
- Toda afirmación de corrección debe incluir evidencia o describirse como hipótesis.

## Artefacto para inspección

**src/locks.rs · lock order** (ejemplo didáctico; no salida real del compilador)

```text
Task A: lock(orders) -> lock(stock)
Task B: lock(stock) -> lock(orders)
```

**Pregunta del reviewer:** Explica el deadlock potencial y cómo definir una política de adquisición.

## Decisión de diseño

Un servicio presenta deadlocks intermitentes; ¿cuál es el primer cambio responsable?

- **Opción A:** Añadir Mutex en todas partes
- **Opción B:** Pasar todo a unsafe
- **Opción C:** Reproducir el orden de locks, medir contención y definir jerarquía

1. Alerta: requests bloqueadas
2. Captura de orden de locks
3. Reproducción y prueba de estrés
