# S17 · Code review con trade-offs

**Tipo:** reto guiado Senior Rust · **ID:** S17-C01 · **Estado:** material práctico preparado; no prueba de ejecución.

## Contexto profesional

Un PR introduce complejidad para resolver una ruta no medida.

## Objetivo del laboratorio

Justificar impacto, alternativas, métricas y riesgos.

## Restricciones y trade-offs

- Comentarios respetuosos con fundamento reproducible.
- Toda afirmación de corrección debe incluir evidencia o describirse como hipótesis.

## Artefacto para inspección

**review.diff · PR con complejidad** (ejemplo didáctico; no salida real del compilador)

```diff
- if failed { return Err(Error::Busy); }
+ match retry(9999, || request()) {
+     Ok(x) => Ok(x),
+     Err(_) => panic!("failed")
+ }
```

**Pregunta del reviewer:** Escribe un comentario de revisión accionable sobre retries sin límite, panic y backpressure.

## Decisión de diseño

Un PR introduce complejidad no justificada; ¿qué hace el reviewer?

- **Opción A:** Rechazar sin explicación
- **Opción B:** Explicar riesgos, pedir evidencia y proponer alternativa mínima
- **Opción C:** Aprobar por seniority del autor

## Evidencias y criterios de aceptación

- [ ] ADR con decisiones y plan de reversión.
- [ ] La explicación diferencia hechos observados de hipótesis.
- [ ] Existe un test adversario que fallaría con la implementación defectuosa.
- [ ] Se documenta la compatibilidad y el riesgo de regresión.
- [ ] La evaluación aclara qué comandos se ejecutaron y cuáles no.

## Secuencia del escenario

1. Diff identificado
2. Comentario accionable
3. ADR solo si decisión difícil de revertir

## Pistas progresivas

1. Enumera qué hechos están observados y cuáles son suposiciones.
2. Identifica el contrato de éxito y el caso adversario mínimo.
3. Define una prueba que fallaría si el problema regresa.

## Quality gates recomendados

- Ejecutar `cargo fmt --all -- --check` y `cargo check --all-targets` en el crate del ejercicio.
- Ejecutar `cargo clippy --all-targets -- -D warnings` y `cargo test` cuando exista un paquete Cargo completo.
- Registrar entorno, versión de toolchain, código de salida y fallos.
- Para async, concurrencia y performance: pruebas de cancelación, estrés, benchmarks o fuzzing según el riesgo, sin fingir resultados.

## Rúbrica de autoevaluación

Correctitud 30 %, fiabilidad y seguridad 25 %, arquitectura 20 %, rendimiento medido 15 % y explicación técnica 10 %. La puntuación local es autodeclarada y no es una certificación.
